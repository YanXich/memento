# 两个参考项目的实测对比与 Memento 的设计取舍

本文档记录对 [pi](https://github.com/earendil-works/pi) 与 [deepseek-harness](https://github.com/deepseek-ai/deepseek-harness) 的**实际运行、源码研读与测试**结论，以及 Memento 在其中的取舍依据。

实测方式：两个项目均克隆到本地并真实运行（pi 通过 CLI 会话实测；deepseek-harness 通过 `pnpm dsh web` 启动 Web UI，浏览器实测 + 截图验证）。

---

## 一、pi —— 极简内核的典范

### 优点

| 维度 | 具体表现 |
| --- | --- |
| **内核极小** | agent loop 只有两层结构，核心逻辑一屏可读。没有"框架感"，更像一组乐高积木。 |
| **JSONL 会话日志** | 每轮一行 JSON，天然可追加、可回放、可 diff，崩溃不丢历史。 |
| **截断安全阀** | 对超长工具输出做确定性的头尾截断，防止上下文被单个命令输出淹没。 |
| **jiti 直接加载 TS 插件** | 插件不需要编译、不需要 manifest、不需要发布流程——写一个 `.ts` 文件即生效。这是插件生态最关键的一步。 |
| **多供应商适配** | DeepSeek / OpenAI / Anthropic 等一视同仁，切换成本极低。 |

### 局限

| 问题 | 影响 |
| --- | --- |
| **无规格引擎** | 没有"项目约定/架构约束"的一等公民表示，模型每次靠现场读代码猜测意图。 |
| **无记忆沉淀** | 会话之间完全失忆。上周踩过的坑，这周原样再踩一遍。 |
| **会话是记录，不是知识** | JSONL 日志只能"看"，不能"用"——没有任何机制把历史经验注入后续会话。 |
| **插件加载一次性** | 加载后缺少系统化的卸载路径，长驻进程的插件热更新不是设计重点。 |

### Memento 从 pi 借鉴了什么

- **双层 agent loop + 截断安全阀**：内核结构直接吸收，保持小与可读。
- **JSONL 会话日志**：`.memento/sessions/*.jsonl` 采用同样的追加式设计，`memento show` 可回放。
- **jiti 免编译插件**：`.memento/plugins/*.ts` 直接加载，零构建步骤。

## 二、deepseek-harness —— 工程纪律的典范

### 优点

| 维度 | 具体表现 |
| --- | --- |
| **能力接缝（capability seams）** | 每个扩展点都是显式接口：工具、事件、检查器……扩展者不需要理解内核。 |
| **可逆注册** | 每次 `register` 返回 disposer，卸载即回滚。插件是"客人"而不是"住户"。 |
| **插件隔离** | 单个插件崩溃不拖垮宿主，错误被捕获并报告到诊断界面。 |
| **单调守卫（monotonic guards）** | 安全约束只增不减：扩展不能悄悄放松既有保护。 |
| **产品级 UI** | Web 界面完整度高：工作区门控、插件面板、设置流、浅色主题、上手引导到位。 |

### 局限

| 问题 | 影响 |
| --- | --- |
| **monorepo 偏重** | pnpm monorepo + 多包结构，贡献者需要理解包边界与构建顺序才能改一行代码。 |
| **上手链路长** | 从克隆到第一次跑通任务，需要装依赖、构建、配置多处，劝退轻度用户。 |
| **同样是"无记忆"架构** | 会话历史不做经验提取，UI 再精致也没有解决"越用越聪明"的问题。 |
| **无规格闭环** | 没有 SDD 概念：没有宪法/架构/决策记录，没有规格校验。 |

### Memento 从 deepseek-harness 借鉴了什么

- **可逆注册的插件 API**：所有注册返回 disposer，`memento doctor` 显示每个插件的贡献与错误。
- **能力接缝的思路**：spec checker 同样走插件接口（`api.spec.registerChecker`）。
- **单调守卫思想**：guard 分类器 fail-safe——无法证明只读的命令一律需要审批，插件不能降低它。
- **诊断优先的体验**：`memento doctor` 一条命令回答"为什么跑不起来"。

## 三、Memento 的取舍：在三者交集处选题

两个项目分别证明了"内核可以多小"（pi）与"工程可以多严"（dsh），但都留了同一个洞：**跨会话的自我进化**。Memento 的选题正是补这个洞，同时保持两者的最佳实践。

| 设计决策 | 采纳自 | 理由 |
| --- | --- | --- |
| 小内核 + JSONL 日志 + jiti 插件 | pi | 已被验证的极简路径，直接复用其正确性 |
| disposer 插件 API + 隔离 + fail-safe 守卫 | dsh | 扩展安全性的工程底线，不能省 |
| **置信度加权的 lessons 记忆** | 原创 | 补两项目共同的洞：经验需要**动力学**，而不是简单的存/删 |
| **可校验的 Markdown 规格（SDD 闭环）** | 原创 | 规格不能只是文档；deterministic checkers 让它"回答"代码的现状 |
| **RECALL→GATE→BUILD→VERIFY→REFLECT 闭环** | 原创 | 把记忆与规格钉进执行流程，而不是可选的附加功能 |
| 零外部依赖的确定性检查 | 两者皆有 | 校验与安全分类永不调用 LLM：模型做判断，代码做检查 |

### 为什么记忆需要"置信度"而不是简单的存/删

朴素方案（同一条经验出现即强化、删除即遗忘）有两个致命问题：

1. **没有证据门槛**：模型幻觉出来的"经验"和真实踩坑得到的经验同权，越用越蠢。
2. **没有纠错路径**：错误的经验只增不减，污染 recall 池。

Memento 的数值设计（初始 `0.35`，强化 `+0.15`，矛盾 `−0.30`，`< 0.12` 退休）刻意让**证伪权重大于证实**：

- 新经验一次矛盾即退休（`0.35 − 0.30 = 0.05`）——第一印象毫无豁免权；
- 被证实过一次的经验（`0.50`）能挺过一次矛盾（`→ 0.20`），第二次才退休——真正可靠的规律经得起偶尔的意外。

所有变动都写在 `lessons.jsonl` 里并附 evidence 字段，可审计、可回滚、可人工 `--reinforce` / `--contradict`。

## 四、结论

- **pi 教会我们**：内核的价值密度。把 agent loop、会话日志、插件加载压缩到可通读的规模，用户才敢改。
- **deepseek-harness 教会我们**：扩展的纪律。可逆注册、错误隔离、单调守卫，让插件生态不至于变成安全事故。
- **Memento 的判断**：两者共同的缺口是**经验流动**——规格把人的意图变成可校验的约束，记忆把机器的经历变成可信的知识，闭环让两者在一次 `memento run` 里自动完成。

目标读者：既想要小巧可黑客的 agent 内核（像 pi），又不想在团队协作中丢失工程纪律（像 dsh）的人。
