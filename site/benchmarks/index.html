The memory benchmark measures the core thesis with numbers: run a family of similar tasks with no memory (cold), then again recalling everything earlier tasks taught (warm). The gap between the two curves is what accumulated lessons are worth — in turns and tokens.

Method — two curves, one delta

cold — the memoryless baseline

A pristine copy of the repo, zero lessons recalled, no reflection afterwards. This is what a memoryless agent costs — every task solved from scratch.

warm — recalled lessons

The shared run directory: every earlier task's lessons are recalled into the system prompt and every run reflects afterwards. This is what memento actually costs.

Reproducibility: --dry runs use a deterministic scripted provider (zero network, identical every time). Real-model runs record provider, model and the tasks.json family. Submission is one command — see below.

Submit your run — one command, then a PR

Pick a family of similar tasks and run the benchmark (deterministic dry run or a real model):
# dry: zero network, reproducible memento bench tasks.json --json --dry > bench-out.json
Merge the run into the leaderboard data (re-runs replace your previous entry):
# report is optional — point at your committed --report HTML node scripts/merge-bench.mjs bench-out.json your-handle --report benchmarks/your-report.html
Open a PR with the changed site/benchmarks/results.json (+ report file). The page is static — no backend, no credentials, nothing but numbers.

Rules: every entry must be reproducible (record provider, model, tasks.json and the dry flag). Same submitter + provider + model + task family = one entry, refreshed in place.
